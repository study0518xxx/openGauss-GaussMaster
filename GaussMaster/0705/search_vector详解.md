# search_vector 详解

## 1. 一句话解释

**将用户问题转为向量，在向量数据库中搜索最相似的知识片段。**

---

## 2. 完整流程图

```
用户问题: "如何创建索引？"
    │
    ▼
┌─────────────────────────────────────┐
│  1. query_embedding()                │
│     调用 Embedding 模型将问题向量化   │
│     "如何创建索引？" → [0.123, -0.456, ...] │
└─────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────┐
│  2. 构造 SQL 查询                    │
│     ORDER BY text_vector <-> [向量]  │
│     LIMIT topk                      │
│     (计算欧氏距离，找最近的K条)       │
└─────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────┐
│  3. 执行 SQL                        │
│     从 GaussDB 向量数据库查询        │
└─────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────┐
│  4. 返回最相似的 topk 条结果         │
└─────────────────────────────────────┘
```

## 3. 核心代码解析

**位置：** `GaussMaster/common/metadatabase/dao/gaussdb_vector.py` 第 177-198 行

```python
async def search_vector(self, query: str, topk: int, version="", embedding_key=None, distance=2):
    # 第1步：获取 embedding_key（默认为第一个向量字段）
    if not embedding_key:
        embedding_key = self.embedding_keys[0]

    # 第2步：将用户问题转为向量
    embedding = await self.embedding_function.query_embedding(query)
    # "如何创建索引？" → [0.123, -0.456, 0.789, ...] (1024维)

    # 第3步：构造 SQL
    embedding_str = [str(num) for num in embedding]
    query_sql = '\'[' + ','.join(embedding_str) + ']\''

    # 第4步：执行向量相似度搜索
    # <-> 是欧氏距离操作符，距离越小越相似
    sql = f'SELECT * FROM "{self.db_index}" '
    sql += f'ORDER BY "{embedding_key}_vector" <-> {query_sql} LIMIT {topk}'

    # 第5步：执行并返回结果
    self._connect()
    self.cur.execute(sql)
    result = self.cur.fetchall()
    self._close()
    return result
```

---

## 4. 距离计算方式

| 方式 | 操作符 | 说明 |
|------|--------|------|
| **L2 距离（欧氏距离）** | `<->` | 默认方式，平面几何距离 |
| **余弦距离** | `<=>` | 夹角余弦值 |
| **内积** | `<#>` | 向量点积 |

---

## 5. 实际 SQL 示例

```sql
-- 用户问题："如何创建索引"
-- 向量：[0.123, -0.456, 0.789, ...]

SELECT * FROM "knowledge_base"
ORDER BY "text_vector" <-> '[0.123,-0.456,0.789,...]'
LIMIT 5
```

---

## 6. 为什么需要向量搜索？

| 传统搜索 | 向量搜索 |
|----------|----------|
| 关键词匹配 | 语义理解 |
| "数据库"只能找到包含"数据库"的文档 | "DBMS"能找到关于数据库的文档 |
| 无法处理同义词 | "电脑"能找到"计算机"相关文档 |
| 机械死板 | 理解意图，灵活智能 |

---

## 7. search_vector 与 search_text 的区别

| 对比项 | `search_vector` | `search_text` |
|--------|-----------------|---------------|
| **原理** | 向量相似度 | BM25 关键词匹配 |
| **搜索内容** | 语义相似 | 字面相同 |
| **性能** | 较快（有索引） | 较慢 |
| **适用场景** | 理解意图 | 精确查找 |

```
└─────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────┐
│  reranker()     ← 重排序            │

```

## 9. 总结

| 步骤 | 操作 | 作用 |
|------|------|------|
| 1 | `query_embedding()` | 将问题转为向量 |
| 2 | 构造 SQL | 构建向量搜索查询 |
| 3 | `ORDER BY <->` | 按距离排序 |
| 4 | `LIMIT topk` | 取最相似的 K 条 |
| 5 | 返回结果 | 提供给 LLM 作为上下文 |
