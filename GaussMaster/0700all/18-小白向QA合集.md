## 1. 为什么用 L2 距离而不是余弦相似度？

**两个原因。**

**实用原因**：GSDiskANN 的 PQ（乘积量化）算法天然基于 L2 距离，在 L2 上跑得最稳。

**理论原因**：BGE 输出的向量已经归一化（长度=1），对于归一化向量，L2 和余弦的排名结果完全一样。

```
公式：L2距离² = 2 - 2 × 余弦相似度

余弦越大 → L2越小，一一对应，排序不变。
就像摄氏度和华氏度——数值不同，但"谁更热"的排名一样。
```

源码中三种都支持，只是默认 L2：
```python
DEFAULT_DISTANCE_STRATEGY = "l2"  # l2/cosine/inner
```

## 2. 归一化是什么？归一和不归一有什么区别？

**归一化 = 把所有箭头削成一样长（长度=1），只保留方向。**

```
不归一化：
  短文向量 = [0.2, 0.1, 0.3]  长度 0.5
  长文向量 = [0.4, 0.2, 0.6]  长度 1.0
  虽然意思一样，但 L2 距离差很大 → 搜不准

归一化后：
  短文向量 = [0.4, 0.2, 0.6]  长度 1
  长文向量 = [0.4, 0.2, 0.6]  长度 1
  意思一样 → 向量一样 → 搜得准
```

BGE 模型训练时就被要求输出归一化向量，所以拿到手的已经是归一化的，不需要额外处理。归一化后 L2 和余弦排序一致，就是这个原因。

## 3. 你们文档数量有多少？类型有什么？

没有固定数字，取决于部署环境。银行实际部署涵盖 GaussDB 全家桶——产品手册、排障指南、API 参考、最佳实践、历史工单。

支持两种文件格式：
- **Markdown**（.md）：标题驱动的层次化分块

PDF 和 HTML 是空壳，还没实现。

## 4. 分块到底是语义分还是按 500 字分？

**两层都做了，不是二选一。**

```
第一刀：按标题切（语义边界）
  遇到 #标题 → 切一刀

第二刀：按长度切（在标题段内部）
  超过 500 字 → 再补一刀
  但代码块、表格、列表、引用 → 不切（保证语义完整）
```

核心常量：
```python
MIN_BLOCK_LENGTH   = 200    # 太短不独立成块
PROPER_BLOCK_LENGTH = 500   # 理想块大小
MAX_BLOCK_LENGTH   = 1000   # 单段上限
```

**为什么是 500 字？**
- 太短（100字）：上下文碎片，LLM 看不懂
- 太长（2000字）：语义稀释，"CPU调优"和"内存调优"混在一起
- 500 字：BGE 模型最佳窗口，语义集中 + 上下文充足

## 5. 工具注册时为什么生成两种格式？

**因为不同模型吃不了一样的喂法。**

盘古云需要 JSON 格式来触发原生 function_call，ChatGLM/Baichuan 只能理解自然语言。

```python
# executor.py:47-53
if llm.llm_type == LLMType.PANGUCLOUD:
    tools_des = detail_dict_list   # JSON 格式
else:
    tools_des = detail_str_list    # 纯文本格式
```

两种格式长这样：

```
字符串格式（给 ChatGLM/Baichuan/Llama3）:
  risk_analysis：预测指标趋势，参数列表：(metric: 指标名称，str类型, required: True)

字典格式（给盘古云，触发原生 function_call）:
  {"name": "risk_analysis", "description": "预测指标趋势", "arguments": [
    {"name": "metric", "type": "str", "description": "指标名称", "required": true}
  ]}
```

**只用一种行不行？** 不行。只用字符串 → 盘古云调不了工具。只用 JSON → ChatGLM 看不懂。六种模型统一适配，各取所需。

## 6. 向量化用的是什么模型？具体怎么向量化的？

**模型**：BGE-large，在 10.6 万条 GaussDB 语料上微调过。1024 维。开源，银行内网可自己部署。

**选 BGE 三个原因**：中文效果好、开源可内网部署和微调、1024 维比 768 维判别力更强。

```yaml
embedding_model:
  model_name: bge-large-finetune
  api_type: bge-large
  api_url: http://内网IP/get_embedding_result
```

**怎么向量化**：不是把模型跑进程里，是独立 HTTP 服务。入库时每条文本调一次接口，拿回 1024 个浮点数，直接存到 `text_vector floatvector(1024)` 列。查询时用户问题也走同样接口，用 `<->` L2 距离算相似度。

## 7. 工具怎么注册和调用的？

**注册**：装饰器模式，一行完成：

```python
@base_tools(
    name="risk_analysis",
    description="预测指标趋势",
    params=[
        Param(name="metric", param_type="str", required=True),
        Param(name="warning_hours", param_type="int", required=False)
    ]
)
def risk_analysis(metric, warning_hours=24):
    ...
```

装饰器自动把函数名、描述、参数 schema 存入 Registry。

**调用**：两阶段 + 确定性校验：

```
阶段一：从 21 个工具里选名字   → LLM → "risk_analysis"
阶段二：填这个工具的参数       → LLM → {"metric":"cpu_usage"}
确定性校验：inspect.signature → 多余丢弃，缺失提示
执行：call_tool("risk_analysis", params)
```

核心保障：LLM 只负责输出"建议"，真正的参数校验用 inspect.signature 做 100% 确定性检查。

## 8. 哪些表是向量化的，哪些不是？

**有向量的表（4 张）**：搜"意思相近"，用 `<->` L2 距离 + GSDiskANN 索引。

| 表名 | 向量列 | 检索方式 | 干什么的 | 存放在哪 |
|------|--------|---------|---------|---------|
| gauss_kb | text_vector floatvector(1024) | 向量 `<->` + BM25 `###` | **知识库主表。** 存所有文档切块后的文本和向量。用户问答时从这里搜相关文档。 | 向量库（psycopg2 直连） |
| custom_knowledge_{id} | 同上 | 同上 | **用户自建知识库。** 用户上传私有文档后动态创建的表，结构和 gauss_kb 一样。 | 向量库（psycopg2 直连） |
| case_op_kb | inspection_vector | `<->` | **历史故障案例库。** 存巡检项的描述和向量，用于匹配历史故障模式。 | 向量库（psycopg2 直连） |
| gm_tool_history_memory | question_vector floatvector(1024) | `<->` | **工具调用经验库。** 存每次 Agent 调工具的问题+工具名+向量。新问题来了向量搜"历史上类似的"，直接复用工具选择。 | 向量库（psycopg2 直连） |

**没向量的表（7 张）**：精确查询，用普通 SQL WHERE。

| 表名 | 怎么查 | 干什么的 | 存放在哪 |
|------|--------|---------|---------|
| qa_record | WHERE user_id=? AND session_id=? | **RAG 问答记录。** 每次 ask_gauss 的问答全量存档（问题+答案+检索参数+点赞点踩）。RAG 路径的多轮上下文就从这读。 | 向量库（psycopg2 直连） |
| knowledge_base | WHERE user_id=? | **知识库管理表。** 存用户创建的知识库的名称、描述、创建时间。一个用户可以有多个知识库。 | 向量库（psycopg2 直连） |
| data_source | WHERE related_kb_id=? | **上传文件记录。** 存用户上传了哪些文件（文件名、关联哪个知识库）。一个知识库可以有多个文件。 | 向量库（psycopg2 直连） |
| tb_interaction_memory | WHERE user_id=? AND session_id=? | **Agent 交互记忆。** 存每次工具调用的详细记录（问题+回答+用了哪个LLM+调了哪个工具+传了什么参数）。AES加密。Agent 路径的多轮上下文从这读。 | MetaDatabase（SQLAlchemy ORM） |
| tb_diagnostic_report | WHERE report_id=? | **诊断报告。** 存多 Agent 协同诊断的完整报告（告警标题、实例、根因、修复建议、诊断过程）。 | MetaDatabase（SQLAlchemy ORM） |
| tb_managed_cluster | WHERE host=? AND port=? | **集群注册表。** 存纳管的 openGauss 集群信息（IP、端口、用户名、密码）。Agent 调工具前从这查要调哪个集群。 | MetaDatabase（SQLAlchemy ORM） |
| dynamic_config | key-value | **运行时配置。** 存本地 SQLite 文件里的动态配置和 AES 加密密钥部件。不依赖 openGauss，挂了也能读。 | 本地 SQLite 文件 |

**为什么有的向量化有的不？** 需要"意思差不多就能搜到"的向量化，只需要"精确匹配"的不需要。

## 9. qa_record 和 tb_interaction_memory 的区别

| | qa_record | tb_interaction_memory |
|---|---|---|
| **谁写的** | RAG 管道（ask_gauss） | Agent 管道（DBA.interact_with_tool） |
| **记什么** | "搜了什么，答了什么，用户满意吗" | "LLM 调了哪个工具，传了什么参数" |
| **有 function_call 吗** | 没有 | 有（JSON） |
| **有用户反馈吗** | 有（like/hate/report） | 没有 |
| **加密吗** | 不加密，明文 | AES-256-CBC 加密 |
| **有本地缓存吗** | 没有，每次查数据库 | 有，先翻 SESSION_QA_HISTORY |
| **向量化了吗** | 没有 | 没有 |

## 10. SESSION_QA_HISTORY 和 SESSION_TOOL_HISTORY 的区别

**两个都是 Agent 工具链专用的内存缓存，RAG 链不用。**

| | SESSION_TOOL_HISTORY | SESSION_QA_HISTORY |
|---|---|---|
| **存什么** | 当前工具名（一个字符串） | 完整对话记录（InteractionMemory 列表） |
| **用途** | 避免重复推断工具名 | 注入 LLM prompt 做多轮上下文 |
| **生命周期** | 一轮工具调用结束就清 | 滑动窗口，最多 history_len 条 |
| **持久化** | 纯内存，重启丢失 | 内存 + MetaDatabase 双写 |
| **例子** | "这轮还在填 risk_analysis 的参数，别重新猜" | "上一轮你问了 CPU，系统调了 risk_analysis 返回 XX" |

## 11. 什么时候数据库有记录但内存没有？

三种情况：

1. **服务重启**：内存清空，数据库还在 → 下次请求自动从数据库回填
2. **滑动窗口淘汰**：内存只保留最近 3 轮，旧记录被 pop 掉 → 数据库全量保留
3. **换了新会话**：sess_002 的内存缓存不存在 → 查数据库，没有就说明这是新会话第一轮

**反过来（内存有、数据库没有）几乎不发生。** 即使发生也只影响一次会话，重启后一致。

---

## 12. 数据库和内存什么时候清空？

| | tb_interaction_memory（数据库） | SESSION_QA_HISTORY（内存） |
|---|---|---|
| **自动清空** | ❌ 没有，一直堆积 | ✅ 滑动窗口自动淘汰旧记录 |
| **手动清空** | destroy_metadatabase() DROP 整库 | 重启服务 |
| **数据丢了能恢复吗** | 不能，DROP 就没了 | 能，从 MetaDatabase 回填 |
| **会满吗** | 会，无限堆积 | 不会，最多 history_len 条 |

## 13. 两个柜台（RAG vs Agent）的白话解释

**咨询柜台（RAG）**：
- 你问"存款利率多少"，柜员翻手册告诉你
- 临走在本子上写一行记录（qa_record）
- 下次来翻本子看看上次问了啥
- **只有本子，不靠脑子记**

**操作柜台（Agent）**：
- 你问"帮我查流水"，柜员说"需要时间段"
- 柜员脑子里记下"这人要查流水"（SESSION_TOOL_HISTORY）
- 你说"上个月"，柜员不用重问"你要办什么"
- 查完流水，脑子再记一条"刚才查了流水，结果XX"（SESSION_QA_HISTORY）
- 脑子记不住的旧事，去档案柜（tb_interaction_memory）翻
- **有脑子（内存）+ 档案（数据库），两套一起用**
