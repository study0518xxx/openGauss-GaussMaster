# GaussMaster 面试速查卡

## 项目一句话描述
基于 LLM 的 openGauss 数据库智能运维 Copilot，覆盖问答、故障诊断、巡检、调优全生命周期，已在银行 34 个场景实现零人工干预。

---

## 高频面试问与答

### Q1: 用了 LangChain 吗？
**A**: 没用。借鉴了 Agent + Tool 的架构思想，但核心链路（三路混合检索、GSDiskANN 索引、多 Agent 交叉审查、工具调用两阶段分离）全部自研。LangChain 的 RetrievalQA 不支持向量+BM25+reranker 三路混合检索，AgentExecutor 的 ReAct 循环在数据库诊断场景下不够可控。

### Q2: 向量数据库用的什么？为什么不用 Milvus？
**A**: 直接用 openGauss 本身作为向量存储。openGauss 是 PostgreSQL 兼容的，支持 `floatvector(1024)` 列类型和原生 GSDiskANN 磁盘向量索引。好处是一张表同时做向量检索和 BM25 全文检索，无需跨系统数据同步，部署简单。

### Q3: DeepSeek Function Call 怎么用的？
**A**: 没用原生 Function Call API。用提示工程分两阶段：第一步让 LLM 从 21 个工具中选出名字，第二步让 LLM 从用户问题中提取参数。工具选择准确率 >95%，参数填充准确率 >99%。

### Q4: 怎么保证 LLM 不调错工具？
**A**: 四层保证——（1）工具 Schema 结构定义（名、描述、参数类型、是否必填）；（2）专用 prompt 模板约束输出格式；（3）`inspect.signature` 校验参数；（4）两步分离降低单次推理难度。多余的参数丢弃，缺失的参数退回重问。

### Q5: RAG 的核心创新？
**A**: 向量检索 + BM25 全文检索双路混合 → BGE-reranker 微调重排序（过滤 score<0 的结果）→ 无结果时降级到 HyDE（LLM 编假设答案再搜）+ 查询改写（拆 3 个子问题）。

### Q6: 安全怎么做的？
**A**: 三层——DFA 敏感词检测器（2 万+词库）做显式过滤；微调 XLNet 模型（<500ms）做隐式风险分类；提示模板自动注入安全指南。

### Q7: 落地效果？
**A**: 中国农业银行部署，34 个数据库运维场景零人工干预。QA 高质量回答率 85.23%（400+ 真实银行问题），工具选择准确率 >95%，参数填充准确率 >99%。

## 技术栈速览

| 层级 | 技术选型 |
|------|---------|
| Web 框架 | FastAPI + Uvicorn（从 Flask 迁移） |
| LLM | 盘古 / DeepSeek / ChatGLM3 / Qwen / Llama3 |
| 嵌入模型 | BGE-large 微调，1024 维 |
| 重排序 | BGE-reranker 微调 |
| 向量数据库 | openGauss 自身（floatvector + GSDiskANN） |
| 文本检索 | BM25（openGauss 原生） |
| 工具注册 | 自研 Registry 装饰器模式 |
| Agent 架构 | 自研层次化多 Agent（DBA 主控 + 专家 Agent） |
| 前端 | Vue.js + Vite + TypeScript |
| 文档处理 | DNN 语义分块 + 全局去重 + 元信息增强 |
