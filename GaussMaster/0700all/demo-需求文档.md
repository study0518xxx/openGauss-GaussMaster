# GaussMaster Demo — 需求文档

## 项目目标

基于 GaussMaster 的核心设计思想，实现一个可在本地运行的轻量级数据库智能运维 Copilot Demo。目的是通过亲手实现的方式，深入理解 RAG 检索管道、工具调用链、流式输出等核心机制，为面试中的技术深度问答提供真实编码经验。

---

## 功能需求

### FR-1：文档加载与知识库构建

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-1.1 | 支持加载 Markdown 格式的数据库文档（准备 3-5 份 openGauss/GaussDB 文档作为素材） | P0 |
| FR-1.2 | 将文档按语义段落切分成块（大小约 500 字，代码块不切割） | P0 |
| FR-1.3 | 调用 embedding 模型将每个块转为向量（BGE-large-zh，1024 维） | P0 |
| FR-1.4 | 将文本块和向量存入向量数据库（Chroma） | P0 |
| FR-1.5 | 支持增量添加文档（不重建整个库） | P1 |

### FR-2：RAG 问答管道

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-2.1 | 用户输入问题后，将问题转为向量 | P0 |
| FR-2.2 | 在向量库中检索 Top-3 最相关的文档块 | P0 |
| FR-2.3 | 将检索到的文档块作为上下文，拼入 LLM prompt | P0 |
| FR-2.4 | 调用 LLM（DeepSeek）生成答案，SSE 流式输出 | P0 |
| FR-2.5 | 如果检索结果为空，给出"未找到相关知识"的降级提示 | P1 |

### FR-3：工具调用

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-3.1 | 定义 2-3 个模拟的数据库运维工具 | P0 |
| FR-3.2 | 工具包括：获取 CPU 使用率、获取慢 SQL 列表、获取数据库连接数 | P0 |
| FR-3.3 | 实现两阶段工具调用：先选工具名，再填参数 | P0 |
| FR-3.4 | 对 LLM 输出的工具名和参数做校验（模拟 inspect.signature） | P0 |
| FR-3.5 | 工具返回结果后，由 LLM 总结成用户可读的自然语言 | P1 |

### FR-4：Web 服务

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-4.1 | 使用 FastAPI + Uvicorn 搭建 HTTP 服务 | P0 |
| FR-4.2 | 提供 `/ask` 路由，支持 RAG 问答（JSON 返回） | P0 |
| FR-4.3 | 提供 `/ask/stream` 路由，支持 SSE 流式输出 | P0 |
| FR-4.4 | 提供 `/tool` 路由，支持 Agent 工具调用 | P0 |
| FR-4.5 | 流式输出使用 `text/event-stream` + `keep-alive`（与 GaussMaster 一致） | P0 |

### FR-5：会话记忆

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-5.1 | 支持多轮对话记忆，最多保留 3 轮 | P0 |
| FR-5.2 | 滑动窗口淘汰：超过 3 轮自动丢弃最早的 | P0 |
| FR-5.3 | 对话历史注入 LLM prompt 作为上下文 | P0 |

### FR-6：配置管理

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-5.1 | 支持通过 `.env` 文件配置 API Key 和模型参数 | P0 |
| FR-5.2 | 支持切换 embedding 模型和 LLM 模型 | P1 |

## 非功能需求

| 编号 | 需求 | 说明 |
|------|------|------|
| NFR-1 | 响应延迟 | 首 token 延迟 < 2 秒（取决于 LLM API 速度） |
| NFR-2 | 可维护性 | 代码分模块：loader / embedder / retriever / agent / tools / memory / engine / main |
| NFR-3 | 文档 | 每个模块有 README 级别的注释，方便面试时直接打开讲解 |
| NFR-4 | 依赖 | 最小化外部依赖，pip install 不超过 10 个包 |

## 不做（与生产版 GaussMaster 的区别）

| 生产版有 | Demo 不做 | 原因 |
|---------|----------|------|
| openGauss + GSDiskANN | 用 Chroma 代替 | 简化部署，聚焦核心逻辑 |
| BM25 全文检索 | 仅用向量检索 | BM25 需要 openGauss 的 `###` 操作符 |
| 多 Agent 协同诊断 | 单 Agent | Demo 规模不需要 |
| DBMind 工具集成 | 模拟工具返回假数据 | 无法连接真实数据库 |
| DFA 敏感词 + XLNet | 不做安全检测 | Demo 不面向真实用户 |
| 用户管理 / 多会话 | 不做 | 单人使用 |
| 盘古 / 多模型 | 仅用 DeepSeek | 降低成本 |
| Vue.js 前端 | 不做前端，纯 API | 用 curl 或浏览器直接调接口，FastAPI 自带 /docs |
| AES 加密存储 | 不做 | Demo 没有敏感数据 |
| MetaDatabase + qa_record | 仅用 Chroma + memory.py | 简化存储，核心流程不变 |

## 验收标准

| 场景 | 预期结果 |
|------|---------|
| 用户输入"CPU 使用率过高怎么办" | 检索到相关文档，LLM 给出基于文档的答案，流式输出 |
| 用户输入"查一下当前 CPU 使用率" | Agent 选工具 `get_cpu_usage`，返回模拟数据，LLM 总结 |
| 用户输入"帮我查慢 SQL" | Agent 选工具 `get_slow_queries`，返回模拟的 SQL 列表 |
| 用户输入"今天天气怎么样" | 检索不到相关文档，提示"未找到相关知识" |
| 重启应用后再问同问题 | 知识库还在（Chroma 持久化），正常回答 |
