### Markdown 解析：10 种正则模式

`utils/split_util_md.py` 定义了一套结构识别规则：

| 模式 | 正则 | 用途 |
|------|------|------|

| LIST | `^[-*+](\s+)` | 无序列表 |
| ORDER_LIST | `^\d+\.(\s+)` | 有序列表 |
| QUOTE | `^>{1,3}` | 引用块 |
| CODE | ` ```[\s\S]*?``` ` | 代码块 |
| TABLE | `<table[^>]*>[\s\S]*?</table>` | HTML表格 |
| VERTICAL_TABLE | `(\|-{1,2})+\|` | Markdown竖线表格 |
| LINK | `!*\[([^\]]*)\]\([^\)]*\)` | 链接提取 |
| FONT | 斜体/粗体/删除线 | 字体格式清理 |

**关键设计：全角标记符**

```python
TABLE_IDENTIFIER  = "￥￥￥￥￥TABLE￥￥￥￥￥"
TITLE_IDENTIFIER  = "￥￥￥￥￥TITLE￥￥￥￥￥"
LIST_IDENTIFIER   = "￥￥￥￥￥LIST￥￥￥￥￥"
CODE_IDENTIFIER   = "￥￥￥￥￥CODE￥￥￥￥￥"
```

为什么用全角 `￥` 而不是 ASCII 标记？因为文档正文中几乎不可能出现这个字符序列，避免和内容冲突。代码块里的 `#` 不会被当成标题——因为先分离代码块再对非代码区域做标题标记。

## 三、去重：MD5 哈希全局去重

`doc_util.py:216-234`：

```python
def deduplication(content_list, split_type='base'):
    unique_content_list = []
    uuid_list = []
    for content in content_list:
        if split_type == 'base':
            # 单块去重：检查当前块的 MD5
            if content['dup_uuid'] in uuid_list:
                continue
            uuid_list.append(content['dup_uuid'])
        elif split_type == 'split':
            # 相邻块去重：检查 前块+当前+后块 三块联合 MD5
            adjacent_uuids = content['prev_dup_uuid'] + content['dup_uuid'] + content['next_dup_uuid']
            if adjacent_uuids in uuid_list:
                continue
            uuid_list.append(adjacent_uuids)
        unique_content_list.append(content)
    return unique_content_list
```

`dup_uuid` 生成（第111行）：

```python
dup_uuid = hashlib.md5(content.encode("utf-8")).hexdigest()
```

"split" 模式下必须用三块联合指纹——因为相邻分块模式有 chunk_overlap=75，同一段文字可能出现在不同块的重叠区域，只靠单块 MD5 无法正确去重。

## 五、向量化模型

### 配置（`misc/model_config.yaml`）

```yaml
embedding_model:
  enable: True
  model_name: bge-large-finetune
  api_type: bge-large
  api_url: http://*.*.*.*:*/get_embedding_result
```

### 为什么选 BGE-large

**1. 中文效果好。** BGE（BAAI General Embedding）是智源研究院开源的中文嵌入模型家族，在 C-MTEB 中文基准上排名靠前。GaussDB 文档绝大部分是中文。

**2. 开源可微调。** 银行内网不能调 OpenAI API。BGE 开源，可以在 10.6 万条 GaussDB 语料上做领域微调，微调后对 GaussDB 专有术语（"GUC参数"、"gs_dump"、"PGXC"）的语义区分能力明显优于通用版本。

**3. 部署简单。** 封装成独立 HTTP 服务，GaussMaster 通过网络调用，模型升级不重启主服务。

### 为什么是 1024 维

```python
# retriever_util.py:67-69
def get_embedding_dimensions(self):
    return 1024
```

这不是一个设计选择，是 **BGE-large 模型的固定输出维度**。BGE 模型族的三个规格：

| 模型 | 维度 |
|------|------|
| bge-small-zh | 512 |
| bge-base-zh | 768 |
| **bge-large-zh** | **1024** |

选 large 而不是 base：去重后知识库文档块在十万级以上，1024 维的向量判别力更强，精度收益大于存储成本。而且 GSDiskANN + PQ 压缩后，实际存储开销可控。

### 调用方式

```python
class OnlineEmbedding():
    async def __embedding(self, queries):
        data = {"query": queries}
        response = await session.post(url=self.url, data=json.dumps(data))
        return response.json()  # 返回 [[0.12, -0.34, ...], ...]
```

独立 HTTP 嵌入服务，单次请求可批量嵌入。
