# 面试高频追问 & 速答

> 从之前的对话中提炼，面试官最容易卡住你的问题。

---

## 1. 为什么向量库和元数据库用两个连接方式（psycopg2 vs SQLAlchemy）？

**不是故意搞两套。** openGauss 的向量操作（`<->` 距离、GSDiskANN 索引、`floatvector` 列）是私有 SQL 扩展，SQLAlchemy 根本不认识。所以有向量的表（gauss_kb、qa_record、gm_tool_history_memory）必须用 psycopg2 原生 SQL。没有向量的表（tb_interaction_memory、tb_clusters）用 SQLAlchemy 更方便——自动建表、连接池、开发时可切 SQLite。

---

## 2. qa_record 和 tb_interaction_memory 为什么不存同一个库？

不是精心设计，是两条代码路径各自顺手存的。RAG 管道用 psycopg2 连向量库，Agent 管道用 SQLAlchemy 连 MetaDatabase，各自在自己打开的连接里写了记录。技术上合到一个库完全没问题，只是开发节奏没往这个方向优化。

---

## 3. 用户对话到底存在哪？

- RAG 问答 → `qa_record` 表（向量库的 vector_dbname）
- Agent 工具交互 → `tb_interaction_memory` 表（MetaDatabase 的 metadatabase）
- 再加上内存缓存：`SESSION_TOOL_HISTORY`（当前正在调哪个工具）和 `SESSION_QA_HISTORY`（工具交互的滑动窗口缓存）

---

## 4. tb_interaction_memory 具体是什么？

一张普通的数据库表，专门记录 Agent 模式的每次 LLM 交互细节。和 qa_record 的核心区别：**它存了 function_call 字段**——LLM 具体调了哪个工具、传了什么参数。qa_record 记的是"这次问答结果怎么样"，tb_interaction_memory 记的是"LLM 中间干了什么"。AES-256-CBC 加密存储。读的时候：内存优先 → 未命中才查表 → 解密后回填缓存。

---

## 5. 为什么默认模型选盘古而不是 DeepSeek？

盘古和 GaussDB 同属华为生态，内网部署权限审批更方便。盘古 38B 在 GaussDB 领域回答质量优于同级别 DeepSeek。但架构保证了模型可插拔——改配置文件两行就能切。

---

## 6. GSDiskANN 为什么比 HNSW 更适合？

银行场景知识库百万级文档块，内存放不下全部向量。GSDiskANN 是磁盘索引，支持 PQ 压缩，内存占用降低约 10 倍。HNSW 是纯内存索引，数据量大时内存扛不住。

---

## 7. 为什么不用 Milvus？

openGauss 本身就是 PostgreSQL 兼容的，自带 floatvector 列和 GSDiskANN 索引。一张表同时做向量+BM25，不需要跨系统。银行内网环境，少一个外部组件就少一个运维负担。

---

## 9. RAG 路径和 Agent 路径的记忆是独立的吗？

**是的，完全独立，互不交叉。**
- RAG 路径（ask_gauss）：读写 qa_record 表，不碰 SESSION_QA_HISTORY
- Agent 路径（DBA.interaction）：读写 tb_interaction_memory + SESSION_QA_HISTORY，不碰 qa_record
- 同一个 user_id + session_id 可以关联两条路径的记录，但代码层面不互相读对方的表

---

## 10. 如果 LLM 被提示注入输出了危险 SQL 怎么办？

不会执行。LLM 不能直接生成 SQL——它只能输出"调哪个工具 + 填什么参数"。真正的 SQL 是工具内部的 DBMind API 拼接的。GaussMaster 层做了 SQL 注入转义（单引号翻倍）和单语句校验（sqlparse），拒绝多语句注入。没有"直接执行 LLM 输出的 SQL"这个路径。

---

## 11. 安全机制如果被绕过了怎么办？

三层兜底：
1. DFA Trie 做第一道快速拦截（2 万+词，<1ms）
2. XLNet 微调分类器做语义兜底（绕开关键词也能识别危险意图）
3. 最根本的防线：危险写操作（如 DROP）根本不注册为可调用工具。LLM 就算被诱导也调不到危险工具

---

## 12. 你觉得这个项目最大的不足是什么？

三个：
1. LLM 层 fallback 不完善——主模型挂了要手动切
2. 诊断树和 Agent 耦合偏紧——理想情况应该解耦为独立的知识表示层
3. 检索结果缓存没做——HyDE 和查询改写的 LLM 调用是最慢的，值得缓存

---

## 13. 从 Flask 迁移到 FastAPI 是怎么回事？

DBMind 早期用 Flask，后来写了 HttpService 抽象层迁移到 FastAPI。GaussMaster 复用了 DBMind 的 HttpService，从立项就是 FastAPI。那个迁移注释是搬家带来的历史痕迹，不是 GaussMaster 自己的经历。

---

## 14. MetaDatabase 是什么？

不是一种新数据库。就是 openGauss 实例里的另一个 database（gauss_meta），用 SQLAlchemy ORM 连接。存放不需要向量能力的元数据表。底层支持 SQLite/openGauss/PostgreSQL/MySQL 切换。

---

## 15. 21 个工具具体怎么注册的？

```python
# 装饰器模式，一行注册
@base_tools(
    name="risk_analysis",
    description="预测指标趋势",
    params=[
        Param("metric", "指标名称", param_type="str", required=True),
        Param("warning_hours", "预测小时数", param_type="int", required=False)
    ]
)
def risk_analysis(metric, warning_hours=24):
    ...
```
Registry 自动把 name、description、params 序列化为两种格式：字符串格式（给普通 LLM prompt）和字典格式（给盘古云的 function_call）。
