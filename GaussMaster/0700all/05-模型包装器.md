# 05 - 模型包装器

## 抽象基类

```python
# GaussMaster/llms/base/BaseLLM.py
class BaseLLM(ABC):
    def __init__(self, model, url, temperature, stream):
        self.name = model
        self.url = url
        self.temperature = temperature
        self.stream = stream

    @property
    @abstractmethod
    def llm_type(self) -> str:
        """返回 LLMType 中定义的类型"""
        pass

    @abstractmethod
    async def invoke(self, prompt: Union[list, str]) -> tuple:
        """返回 (content, function_call_dict)"""
        pass
```

## LLM 注册表

```python
# GaussMaster/llms/__init__.py
llm_registry = Registry()

from .Pangu import Pangu
from .Chatglm import Chatglm
from .Baichuan import Baichuan
from .Llama import Llama3
from .pangu_cloud import PanguCloud
```

每个模型类通过 `@llm_registry(name='Pangu')` 装饰器注册到全局注册表。

## 支持的模型

| 模型 | 适配器类 | 注册名 | 特殊处理 |
|------|---------|--------|---------|
| 盘古智子（华为） | `Pangu` | Pangu | 原生 `function_call` 字段 |
| 盘古云 | `PanguCloud` | PanguCloud | 自定义 function_call 标记 |
| ChatGLM3 | `Chatglm` | Chatglm | 纯文本，无 function_call |
| 百川2 | `Baichuan` | Baichuan | SSE 流式响应 |
| Llama3 | `Llama3` | Llama3 | 简单 POST + JSON |
| DeepSeek | **通用 HTTP 路径** | — | OpenAI 兼容 API |
| Qwen | **通用 HTTP 路径** | — | OpenAI 兼容 API |

## 两种调用路径

### 路径 1：LLM 类路径（工具交互场景）
用于需要 function_call 字段的场景，通过注册表实例化：

```python
# GaussMaster/multiagents/agents/dba.py
def instantiate_llm(model_name: str):
    llm_config = global_vars.llm_config
    model_params = llm_config.get('online_llm').get(model_name)
    model_type = model_params.get('api_type')   # 如 'Pangu'
    api_url = model_params.get('api_url')
    
    # 从注册表获取类并实例化
    llm = llm_registry.get(model_type)(model_name, api_url)
    return llm

# 调用
tool_name, _ = await llm.invoke(messages)
```

### 路径 2：通用 HTTP 路径（RAG 问答场景）
用于只需要文本回复的场景，直接 POST：

```python
# GaussMaster/server/web/data_transformer.py
async def generate_answer(messages, model_name):
    params = {'messages': messages}
    url = global_vars.llm_config.get('online_llm').get(model_name).get('api_url')
    
    # 直接 SSE 流式请求
    llm_generator = await thread_request_from_llm(url, headers, params)
    for chunk in llm_generator:
        yield chunk
```

DeepSeek 和 Qwen 走路径 2，因为它们的 API 是 OpenAI 兼容的，直接用 `/chat/completions` 端点就行。

### PanguCloud
```python
@llm_registry(name='PanguCloud')
class PanguCloud(BaseLLM):
    llm_type = LLMType.PANGUCLOUD
    
    async def invoke(self, prompt):
        # 使用自定义 <unused2>...<unused3> 标记解析 function_call
```

### ChatGLM3 / Baichuan / Llama3
纯文本模型，`invoke` 返回 `(content, None)`（无 function_call）。工具调用通过提示工程实现。

## generate 和 call 的区别

| 方法 | 场景 | 返回类型 | 使用模型 |
|------|------|---------|---------|
| `generate_answer()` | RAG 问答 | SSE 流（逐字返回） | 通用 HTTP 路径，任意模型 |
| `llm.invoke()` | 工具交互 | `(content, function_call_dict)` | LLM 注册表中的适配器类 |

- `generate_answer` = 通用的文本生成，底层是 HTTP POST + SSE 流解析
- `llm.invoke()` = 模型特定的调用，需要 `function_call` 字段时用盘古适配器，DeepSeek 等走提示工程

## LLM 类型枚举

```python
# GaussMaster/llms/llm_utils.py
class LLMType:
    PANGU = 'pangu'
    PANGUCLOUD = 'pangu_cloud'
    CHATGLM = 'chatglm'
    BAICHUAN = 'baichuan'
    LLAMA3 = 'llama3'
```

注意：没有 DeepSeek / Qwen 条目，因为它们走通用 HTTP 路径，不经过 LLM 类抽象。
