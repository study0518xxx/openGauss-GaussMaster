# 数据库与元数据层面试题

## 一、基础问题

### Q1: 项目用了哪些数据库？分别存什么？

**回答要点**：
| 数据库 | 类型 | 存储内容 |
|:---|:---|:---|
| openGauss | 关系型 + 向量扩展 | 交互记忆、集群信息、诊断报告、知识库元信息、向量数据 |

**为什么选 openGauss**：
- 项目本身就是 openGauss 生态的产品，技术栈统一
- openGauss 支持向量扩展（`floatvector` + `gsdiskann` 索引），一个数据库满足两种需求
- 减少运维复杂度，不需要额外维护向量数据库（如 Milvus）

---

### Q2: 数据库连接是怎么管理的？

**回答要点**：
- 使用 **SQLAlchemy + psycopg2**
- 连接池配置（`result_db_session.py`）：
  ```python
  engine = create_engine(
      url,
      pool_size=10,           # 连接池大小
      max_overflow=10,        # 超出时的额外连接
      pool_pre_ping=True,     # 自动检测连接是否有效
      pool_recycle=3600       # 连接回收时间
  )
  ```
- **自动重连**：`pool_pre_ping=True` 在获取连接前发送 ping，断线自动重建

### Q3: ORM 模型是怎么定义的？

**回答要点**：
- 使用 SQLAlchemy 声明式基类（`metadatabase/base.py`）：
  ```python
  ResultDbBase = declarative_base()
  ```
- 示例（`interaction_memory.py`）：

  class InteractionMemory(ResultDbBase):

## 二、进阶问题

### Q4: 向量表是怎么设计的？

**回答要点**：
- 向量字段类型：`floatvector(1024)`
- 索引：`gsdiskann`，支持近似最近邻搜索
- 距离度量：L2（欧氏距离）、余弦相似度、内积
- 表结构配置（`kb_config.py`）：
  ```python
  KT_TABLE_CONFIG = {
      "vector_field": ['text_vector'],
      "bm25_field": ['text'],
      "text_field": ['text', 'title', 'source', 'version']
  }
  ```

### Q6: 数据库 SSL 是怎么配置的？

**回答要点**：
- `ssl.py` 中通过 `functools.partial` 修改 `psycopg2.connect`：
  ```python
  psycopg2.connect = functools.partial(
      psycopg2.connect,
      sslmode='verify-ca',
      sslcert=ssl_certfile,
      sslkey=ssl_keyfile,
      sslrootcert=ssl_ca_file
  )
  ```
- 配置来源：`gaussmaster.conf` 的 `[Vector]` section
- 支持模式：`disable`、`prefer`、`verify-ca`

## 三、深挖问题

### Q7: 如果数据库连接池满了，系统怎么处理？

**回答要点**：
- `max_overflow=10`：超出 `pool_size` 时，最多创建 10 个额外连接
- 如果还是满了，SQLAlchemy 会等待（默认不超时）
- **优化方向**：
  1. 增加 `pool_size`（根据并发量调整）
  2. 增加 `pool_timeout`（避免无限等待）
  3. 使用连接池监控，及时发现泄漏

---

### Q8: 向量检索的性能怎么优化？

**回答要点**：
1. **索引选择**：
   - 数据量小：暴力搜索（精确但慢）
   - 数据量大：`gsdiskann`（近似但快）
2. **向量维度**：1024 维是权衡了精度和性能，可以考虑降维（PCA）
3. **分片**：数据量大时按用户或知识库分表
4. **缓存**：热门查询结果缓存，减少重复检索

---

### Q9: 数据库迁移/升级是怎么做的？

**回答要点**：
- `ddl.py` 定义表结构
- 初始化时检查表是否存在，不存在则创建
- 目前没有使用 Alembic 等迁移工具，表结构变更需要手动执行 DDL
- **优化方向**：引入 Alembic 做版本化迁移

---

### Q10: 如果让你设计数据库层的高可用，你会怎么做？

**回答要点**：
1. **主从复制**：openGauss 支持流复制，读写分离
2. **连接池高可用**：配置多个数据库地址，故障自动切换
3. **数据备份**：定期全量 + 增量备份
4. **监控告警**：连接数、慢查询、磁盘空间监控

## 四、手写代码题

### 题目：实现一个简单的连接池

```python
import queue
import threading

class SimpleConnectionPool:
    def __init__(self, factory, max_size=10):
        self.factory = factory  # 创建连接的工厂函数
        self.max_size = max_size
        self.pool = queue.Queue(maxsize=max_size)
        self.lock = threading.Lock()
        self.current_size = 0
    
    def get_connection(self):
        try:
            # 优先从池里取
            return self.pool.get(block=False)
        except queue.Empty:
            # 池空了，创建新连接（不超过上限）
            with self.lock:
                if self.current_size < self.max_size:
                    self.current_size += 1
                    return self.factory()
            # 超过上限，等待
            return self.pool.get(block=True, timeout=5)
    
    def release_connection(self, conn):
        try:
            self.pool.put(conn, block=False)
        except queue.Full:
            # 池满了，直接关闭
            conn.close()
            with self.lock:
                self.current_size -= 1
    
    def close_all(self):
        while not self.pool.empty():
            conn = self.pool.get()
            conn.close()
```
