# 面试技巧汇总

> 基于 GaussMaster 项目，面向 AI Agent 开发岗。

---

## 一、万能表达公式：每段话 5 句撑满 2 分钟

```
① 这是干什么的（1 句）
② 不这么做会怎样 / 别人怎么做的（1 句）
③ 我怎么做的（1-2 句，说细节、说数字）
④ 为什么这么选而不是另一种（1 句）
⑤ 效果 / 落地数据（1 句）
```

### 套用示例

**不讲**："我做了两阶段工具调用，准确率从 60% 提到 95%。" → 30 秒没词了

**这样讲**：

> ① 系统需要让 LLM 去调用数据库诊断工具。② 业界通常用原生 Function Call API，但每个模型格式不一样——盘古的字段名和 DeepSeek 完全不同，ChatGLM 根本没有。③ 所以我设计了模型无关的两阶段方案：阶段一让 LLM 从 21 个工具里选名字，阶段二把工具 schema 给它填参数，输出 JSON 后用 inspect.signature 做确定性校验。④ 为什么不用 LangChain AgentExecutor？因为它的 ReAct 循环在诊断场景会跳过关键步骤，我们的诊断树方案更可控。⑤ 21×3=63 维拆成 21+3 维，准确率从 60% 提到 95%+，在 1614 个银行真实问题上验证的。

## 二、被问住时的万能话术

面试官问到你不会的，**不要说 "我不知道"**。用这三句：

| 场景 | 话术 |
|------|------|
| 概念知道但没做过 | "这个我了解原理，但在项目里还没实际用到。如果要做的话，我会……" |
| 完全没接触过 | "这块我之前没涉及过，但听起来和 XX 有点像。能简单介绍一下吗？" |
| 确实答不上来 | "这个我需要查一下，以我目前的理解，可能是……方向对吗？" |

**核心**：把 "不会" 变成 "对话"。面试官不是考你，是看你遇到不懂的东西怎么反应。

---

## 三、主动把话题往你熟悉的方向拽

面试官的提问是散的，但你的回答可以是**聚**的。每个回答的最后一句，抛一个你可以继续深入讲的钩子。

```
面试官: "你们怎么做监控的？"

你: "监控这块我们目前还在规划——但说到稳定性，
     我想提一下 Agent 工具调用里的参数校验。
     我们用 inspect.signature 做确定性校验，
     多余的参数直接丢弃，缺失的提示补充。
     这比靠 prompt 约束靠谱得多——prompt 是 99%，代码是 100%。"
     ↑ 把 "监控" 拽回你最熟的 "参数校验"
```

## 四、最有杀伤力的反问

面试官："你有什么想问我的吗？"——**不要问公积金和加班**。问这个：

> "你们的 AI Agent 目前是跑在什么场景下的？遇到的最大挑战是什么？"

杀伤力：
- 说明你不是来混工作的，你真的关心技术
- 他说出来挑战后，你可以接——"这个我们项目里也遇到过，我们是这么处理的……"
- 把 "他面试你" 变成 "你们在聊技术"，平等的

---

## 五、面试时 IDE 摆在屏幕左边

电脑上开着 VS Code。面试官让你讲项目时，**直接切到代码，边看边讲**：

> "你看这块——split_util_md.py 第 634 行——这是分块的核心逻辑。"

- 你不会忘词——代码就是提词器
- 面试官觉得你是真的写过——敢打开代码讲的人不可能造假
- 自然就有细节——你看到变量名、注释，随口就能讲出来

## 六、数字比形容词有用十倍

| 不要说 | 要说 |
|--------|------|
| "检索效果挺好的" | "Recall@3 在 400 个测试问题上 85%+" |
| "准确率提升了很多" | "60% 提升到 95%" |
| "模型做了微调" | "10.6 万条 GaussDB 语料微调" |
| "内存占用不大" | "PQ 压缩后 100 万条向量只占 500MB" |
| "用的嵌入模型很好" | "BGE-large-zh，1024 维，C-MTEB 前三" |
| "回答质量不错" | "银行 400+ QA 对，高质量率 85.23%" |

**没有数字的句子 = 没有说服力的句子。** 面试官一天面 5 个人，能记住的一定是带数字的。

---

## 七、最后一个问题前的准备

面试官通常在最后 5 分钟问 "还有什么想补充的吗？"

**把你最想让他记住的一句话留到现在说**：

> "其实这个项目最核心的，不是用了什么技术栈——是我们在每个环节都做了 '为什么' 的选择。为什么不用 LangChain、为什么不用 Function Call、为什么不用 Milvus——每个选择背后都有具体的业务原因。这种做决策的能力，比会用某个框架更重要。"

## 八、核心记忆清单（面试前扫一眼）

### 5 句话 —— 项目是什么

```
1. 基于 LLM 的数据库智能运维 Copilot，34 个场景零人工干预
2. RAG 管道：向量 + BM25 双路混合 → reranker 重排 → HyDE 降级
3. Agent：两阶段工具调用（先选工具名再填参数），60%→95%
4. 不用 LangChain，不用原生 Function Call，全部自研
5. 银行生产环境落地，1614 个真实问题验证
```

### 4 个必背数字

```
1024 维     → BGE-large-zh 微调版
10.6 万     → GaussDB 语料微调量
60%→95%    → 两阶段准确率提升
85.23%     → QA 高质量率
```

### 3 个最有区分度的 "为什么"

```
为什么不用 LangChain → openGauss 原生向量+BM25 同表操作，LangChain 的抽象层反而变成负担；ReAct 诊断不可控
为什么不用 Function Call → 6 种模型格式不一样，提示工程统一适配
为什么不用 Milvus → openGauss 一张表同时做向量+BM25，不跨系统
```

## 十、面试前最后一天

**不要再看文档。** 打开 IDE，对着代码自言自语讲一遍：

```
打开 split_util_md.py → 讲分块（1.5 分）
打开 retriever_util.py → 讲混合检索（1.5 分）
打开 data_transformer.py → 讲 RAG 管道（2 分）
打开 dba.py → 讲两阶段工具调用（2 分）
打开 main.py → 讲整体架构（1 分）
```

卡壳的地方看一眼文档。重复 3 遍。**你是开发者，不是背诵机器。代码就是你的提词器。**
